# Как выложить сайт ФРСРК в интернет: инструкция по шагам

Эта инструкция написана так, чтобы её мог выполнить человек, который никогда не делал сайтов. Идите по шагам сверху вниз. Не перескакивайте. После каждого шага есть пункт «Как понять, что всё получилось».

Если название кнопки на сайте сервиса чуть отличается от того, что написано здесь, ищите кнопку с похожим смыслом. Сервисы иногда переименовывают кнопки.

---

## Сначала простая картинка: из чего состоит сайт

Представьте, что сайт это магазин.

| Что в магазине | Как это называется в интернете | Какой сервис используем |
|---|---|---|
| Адрес магазина на вывеске | Домен, например `frsrk.ru` | reg.ru (вы уже купили) |
| Чертежи магазина | Код сайта | GitHub |
| Само здание магазина | Сервер, где работает сайт | Timeweb Cloud, раздел «App Platform» |
| Картотека с записями (новости, календарь, секции) | База данных | Timeweb Cloud, раздел «Базы данных» |
| Склад с тяжёлыми вещами (документы, музыка, фото) | Файловое хранилище S3 | Timeweb Cloud, раздел «Хранилище S3» |
| Кабинет директора, где всё меняют | Админка на адресе `/admin` | Уже есть в сайте |

Важно: документы, музыка и фотографии лежат на «складе» (S3), а не внутри сайта. Поэтому сайт остаётся лёгким, а файлы можно менять без программиста.

---

## Что вам понадобится

- Компьютер Mac (у вас он есть).
- Почта, к которой у вас есть доступ.
- Банковская карта для оплаты Timeweb Cloud. Оплата идёт помесячно или почасово, в зависимости от услуги. Точные цены смотрите на сайте timeweb.cloud перед оплатой.
- Аккаунт на GitHub (у вас есть).
- Домен на reg.ru (у вас есть).
- Папка проекта `frsrk_v3` на вашем компьютере.

Сохраните все пароли и ключи, которые будете получать, в менеджер паролей или в надёжное место. Не отправляйте их никому и не вставляйте в чаты.

## Шаг 0. Подготовить компьютер

Нужно поставить две программы: Node.js (запускает сайт) и Git (отправляет сайт на GitHub).

1. Откройте программу **Терминал** (нажмите ⌘ + пробел, напишите «Терминал», нажмите Enter). Это чёрное или белое окно, куда вводят команды.
2. Проверьте, есть ли Node.js. Введите и нажмите Enter:

   ```
   node -v
   ```

   Если увидели `v24.…`, всё хорошо. Если написано «command not found», поставьте так:

   ```
   brew install node@24
   ```

   Если Терминал ответил, что нет команды `brew`, сначала зайдите на сайт brew.sh и скопируйте оттуда одну длинную команду установки. Вставьте её в Терминал и подождите.

3. Проверьте Git:

   ```
   git --version
   ```

   Если написано «command not found», macOS сама предложит установить инструменты разработчика. Согласитесь и подождите.

4. Перейдите в папку проекта:

   ```
   cd ~/Documents/web-site-frsrk/frsrk_v3
   ```

5. Установите всё, что нужно сайту:

   ```
   npm install
   ```

   Подождите 2 или 3 минуты. Красные предупреждения про «deprecated» можно не читать.

**Как понять, что всё получилось:** команда закончилась без слова `error` в конце, и появилась папка `node_modules`.

## Шаг 1. GitHub: положить чертежи сайта на хранение

GitHub хранит код сайта и присылает его на сервер Timeweb.

### 1.1. Создать пустой репозиторий

1. Зайдите на github.com и войдите в свой аккаунт.
2. Нажмите зелёную кнопку **New** (или значок «+» справа вверху, потом **New repository**).
3. В поле **Repository name** напишите `frsrk-site`.
4. Выберите **Private** (закрытый). Это важно: так код видите только вы.
5. Галочки «Add a README», «.gitignore» и «license» **не ставьте**.
6. Нажмите **Create repository**.

GitHub покажет страницу с адресом репозитория вида `https://github.com/ВАШ-НИК/frsrk-site.git`. Скопируйте его.

### 1.2. Отправить проект

Вернитесь в Терминал (вы всё ещё в папке `frsrk_v3`). Вводите команды по одной. Вместо `ВАШ-НИК` подставьте свой ник с GitHub.

```
git init -b main
git add .
git status
```

Команда `git status` покажет список файлов. **Проверьте, что в списке нет файлов `.env`, `.env.prod` и папки `seed-assets`.** Это ваши секреты и тяжёлые файлы, они специально исключены. Если вы их видите, остановитесь и напишите разработчику.

```
git commit -m "Первая версия сайта ФРСРК"
git remote add origin https://github.com/ВАШ-НИК/frsrk-site.git
git push -u origin main
```

Если Git попросит войти, откроется окно браузера. Согласитесь на вход в GitHub. Если попросит «пароль», вместо пароля нужен специальный токен: на github.com откройте Settings, Developer settings, Personal access tokens, создайте токен с правом `repo` и вставьте его вместо пароля.

**Как понять, что всё получилось:** обновите страницу репозитория на GitHub. Там появились папки `src`, `docs`, файл `Dockerfile`. Файла `.env` там нет.

## Шаг 2. Timeweb Cloud: регистрация

1. Откройте timeweb.cloud и нажмите **Регистрация** (или **Войти**, если аккаунт уже есть).
2. Подтвердите почту и телефон.
3. Пополните баланс. Для начала хватит небольшой суммы, но лучше положить чуть больше, чтобы услуги не отключились.
4. В панели создайте **проект** (кнопка «Создать проект» или раздел «Проекты»). Назовите его `ФРСРК`. Все услуги ниже будем создавать в этом проекте, так их проще найти.

Выбирая регион и дата-центр для любой услуги, выбирайте **Россию**. Так персональные данные посетителей остаются на серверах в России, как требует закон.

## Шаг 3. База данных (картотека)

1. В левом меню откройте **Базы данных** и нажмите **Создать**.
2. Выберите тип **PostgreSQL**. Версию выберите самую новую из доступных, не ниже 15.
3. Регион: Россия. Тариф: самый маленький подойдёт для начала, потом можно увеличить.
4. Придумайте имя, например `frsrk-db`, и проект `ФРСРК`. Нажмите **Заказать** или **Создать**.
5. Подождите 1 или 2 минуты, пока база станет «Запущена».
6. Откройте созданную базу. Найдите вкладку **Подключение** (или **Доступ**). Там написаны:
   - **Хост** (адрес сервера базы),
   - **Порт** (обычно 5432),
   - **Пользователь**,
   - **Пароль**,
   - **Имя базы**.

7. Внешний доступ. Чтобы вы смогли загрузить документы с Mac (шаг 8), базе нужен доступ снаружи. В настройках базы найдите пункт про **внешний доступ** или **IP-адреса** и разрешите подключения. Для безопасности потом можно оставить только свой адрес.

### Соберите адрес подключения (DATABASE_URL)

Это одна строка, в которую вставляются данные из вкладки «Подключение»:

```
postgresql://ПОЛЬЗОВАТЕЛЬ:ПАРОЛЬ@ХОСТ:5432/ИМЯ_БАЗЫ
```

Пример с выдуманными данными:

```
postgresql://gen_user:Abc123xyz@1.2.3.4:5432/default_db
```

Если в пароле есть символы `@`, `#`, `/`, `:` или `%`, их нужно заменить кодами: `@` на `%40`, `#` на `%23`, `/` на `%2F`, `:` на `%3A`, `%` на `%25`. Проще всего попросить Timeweb сгенерировать пароль без таких символов.

Сохраните эту строку, она понадобится дважды: в шаге 5 и в шаге 8.

**Как понять, что всё получилось:** статус базы «Запущена», и у вас есть строка DATABASE_URL.

## Шаг 4. Хранилище S3 (склад для файлов)

1. В левом меню откройте **Хранилище S3** и нажмите **Создать**.
2. Класс хранения выберите **Стандартный**. Тариф самый маленький, можно включить автомасштабирование, чтобы место росло само.
3. Тип бакета выберите **Публичный**. Публичный нужен, чтобы посетители сайта могли открывать документы и слушать музыку.
4. Имя бакета: только маленькие латинские буквы, цифры и дефисы, например `frsrk-files`. Имя должно быть уникальным на всём Timeweb, если такое занято, добавьте цифры.
5. Регион: Россия. Нажмите **Создать**.
6. Откройте бакет и найдите данные доступа. Они могут называться **Access Key** и **Secret Key** (или «Ключ доступа» и «Секретный ключ»). Там же указан **Endpoint** (адрес хранилища). Обычно это `https://s3.twcstorage.ru`, а регион `ru-1`. Запишите то, что показывает ваша панель.

Соберите четыре значения:

| Переменная | Что писать | Пример |
|---|---|---|
| `S3_ENDPOINT` | адрес хранилища из панели | `https://s3.twcstorage.ru` |
| `S3_REGION` | регион из панели | `ru-1` |
| `S3_BUCKET` | имя вашего бакета | `frsrk-files` |
| `S3_ACCESS_KEY_ID` | Access Key | длинная строка |
| `S3_SECRET_ACCESS_KEY` | Secret Key | ещё более длинная строка |
| `S3_PUBLIC_URL` | endpoint и имя бакета через слэш | `https://s3.twcstorage.ru/frsrk-files` |

Важно: `S3_PUBLIC_URL` это тот адрес, по которому браузер посетителя открывает файл. Проверить его можно потом: когда файл загрузится, ссылка на него должна открываться в браузере. Если открывается ошибка доступа, значит бакет не публичный: проверьте пункт 3.

**Как понять, что всё получилось:** бакет создан, и у вас записаны 6 значений из таблицы.

## Шаг 5. Сервер сайта (App Platform)

Здесь Timeweb берёт код с GitHub и запускает сайт.

1. В левом меню откройте **App Platform** и нажмите **Создать**.
2. Выберите иконку **GitHub**, войдите и разрешите доступ к репозиторию `frsrk-site`.
3. Выберите репозиторий `frsrk-site` и ветку `main`.
4. Включите переключатель **Сборка по последнему выполненному коммиту**. Тогда сайт сам обновляется после каждой отправки на GitHub.
5. В пункте **Фреймворк** должно быть выбрано **Dockerfile**. Если выбрано другое, поменяйте.
6. Регион: Россия. Тариф: возьмите не самый слабый. Сайту нужно не меньше 1 ГБ памяти, лучше 2 ГБ.
7. Нажмите **Показать расширенные настройки** и найдите раздел **Переменные**. Добавьте переменные из таблицы ниже. Название слева, значение справа.

| Название | Значение |
|---|---|
| `DATABASE_URL` | строка из шага 3 |
| `PAYLOAD_SECRET` | придумайте длинную случайную строку из 40 и больше символов (буквы и цифры) и сохраните её |
| `NEXT_PUBLIC_SITE_URL` | пока адрес, который выдаст Timeweb (с `https://`, без слэша на конце). Потом заменим на ваш домен |
| `S3_ENDPOINT` | из шага 4 |
| `S3_REGION` | из шага 4 |
| `S3_BUCKET` | из шага 4 |
| `S3_ACCESS_KEY_ID` | из шага 4 |
| `S3_SECRET_ACCESS_KEY` | из шага 4 |
| `S3_PUBLIC_URL` | из шага 4 |

Как быстро придумать `PAYLOAD_SECRET`: в Терминале введите `openssl rand -hex 32` и скопируйте результат.

Если вы пока не знаете адрес сайта, впишите любой временный, например `https://example.ru`, а после первого запуска замените на настоящий и нажмите «Перезапустить».

8. Дайте приложению имя `frsrk-site`, выберите проект `ФРСРК` и нажмите **Запустить деплой**.
9. Откройте вкладку **Деплой** и следите за журналом. Первая сборка идёт примерно 5 или 8 минут. Внизу журнала должно быть сообщение об успешном запуске.
10. На вкладке **Дашборд** найдите **технический домен** (адрес вида `что-то.twc1.net`) и IP-адрес. Запишите оба.

Если вы вписали временный `NEXT_PUBLIC_SITE_URL`, замените его теперь на технический домен и перезапустите приложение.

### Проверка

Откройте в браузере `https://ВАШ-ТЕХНИЧЕСКИЙ-ДОМЕН/api/health`. Должно появиться `{"status":"ok"}`. При первом открытии сайт сам создаёт нужные таблицы в базе, это занимает несколько секунд.

**Как понять, что всё получилось:** страница `/api/health` отвечает `ok`, а главная страница открывается (пока без картинок и текстов, это нормально: мы их загрузим на шаге 8).

Если что-то не так, смотрите раздел «Что делать, если сломалось» в конце.

## Шаг 6. Создать администратора (сделайте это сразу!)

Пока в базе нет ни одного сотрудника, любой человек, узнавший адрес, может открыть `/admin` и стать администратором. Поэтому этот шаг делают первым делом после запуска.

1. Откройте `https://ВАШ-ТЕХНИЧЕСКИЙ-ДОМЕН/admin`.
2. Появится форма «Добро пожаловать. Чтобы начать, создайте первого пользователя». Введите почту, пароль (два раза), имя. Поле «Роль» можно не трогать: первый сотрудник всегда становится администратором. Пароль не короче 12 символов, с цифрами и буквами.
3. Нажмите кнопку **Создать**. Вы вошли в админку как **Администратор**.
4. Запишите пароль в надёжное место.

**Как понять, что всё получилось:** вы видите панель с пунктами «Содержимое», «Файлы», «Система».

Позже, в разделе «Система → Сотрудники», можно добавить других людей с ролью «Редактор». Редактор может менять содержимое сайта, но не может добавлять сотрудников.

## Шаг 7. Проверить, что файлы попадают на склад

1. В админке откройте **Файлы → Изображения** и нажмите **Создать**.
2. Загрузите любую картинку, в поле описания напишите «проверка».
3. После сохранения нажмите на файл. В карточке будет ссылка. Скопируйте её и откройте в новой вкладке.

Если картинка открылась, склад работает. Удалите тестовую картинку.

Если вместо картинки появилась ошибка (например, `AccessDenied`), бакет непубличный или `S3_PUBLIC_URL` написан неверно.

## Шаг 8. Загрузить документы, музыку, тексты и данные

На вашем компьютере уже лежит всё, что нужно загрузить: 20 документов, 16 звуковых дорожек, готовые тексты страниц, 26 записей на карте (25 муниципальных образований Крыма и Севастополь), руководство, секции, календарь. Это делает одна команда. Она отправляет файлы прямо на склад S3 и записывает данные в базу.

1. В папке `frsrk_v3` создайте файл `.env.prod`. В Терминале введите:

   ```
   cp .env.example .env.prod
   open -e .env.prod
   ```

   Откроется текстовый редактор. Впишите те же значения, что в шаге 5 (DATABASE_URL, PAYLOAD_SECRET, S3 и так далее). Строки, которые вы не используете (SMTP), можно оставить пустыми. Сохраните файл (⌘ + S).

   **Важно:** `PAYLOAD_SECRET` в этом файле должен совпадать с тем, что в Timeweb.

2. Убедитесь, что рядом лежит папка `seed-assets` (в ней документы, музыка и фотографии). Она уже есть в вашей папке проекта.

3. Запустите загрузку:

   ```
   npm run seed:prod
   ```

4. Терминал будет писать, что добавляет. Он покажет строки со знаком `+`. Загрузка 16 звуковых дорожек и 20 документов занимает от 3 до 10 минут, всё зависит от скорости интернета. Ничего не закрывайте, пока не появится «Готово.».

Команду можно запускать повторно: то, что уже загружено, она пропускает и ничего не дублирует.

Что попало на сайт сразу:

- Опубликовано: Устав, приказ и уведомление об аккредитации, Правила вида спорта, положения, ЕВСК, программы, музыка, тексты страниц, секции, руководство, 2 мероприятия.
- **Скрыто, ждёт вашей проверки:** приказы о разрядах и судейских категориях и списки сборной (в них фамилии людей, в том числе детей). Скрытые материалы видны только в админке.
- **Фотоархив** (33 фотографии с соревнований) уже опубликован в разделе «Медиа», первые пять снимков показаны на главной. На фото дети: перед запуском проверьте согласия родителей. Если их нет, откройте в админке **Содержимое → Фотоальбомы → Фотоархив федерации** и снимите галочку «Показывать на сайте».

**Как понять, что всё получилось:** откройте сайт. На главной есть большая картинка, в разделе «Документы» есть файлы, в «Музыка для соревнований» играют дорожки.

## Шаг 9. Подключить домен из reg.ru

Домен это адрес сайта. Сейчас сайт открывается по техническому адресу Timeweb. Теперь привяжем к нему ваш домен.

### 9.1. Добавить записи в reg.ru

Нужно сказать интернету: «когда набирают наш домен, идите на IP-адрес сервера Timeweb». Для этого в reg.ru добавляют записи.

1. Зайдите на reg.ru и войдите в личный кабинет.
2. Откройте **Домены и услуги** и выберите ваш домен.
3. Найдите пункт **DNS-серверы и управление зоной** и перейдите в управление зоной.
4. Убедитесь, что у домена стоят DNS-серверы reg.ru (обычно `ns1.reg.ru` и `ns2.reg.ru`). Если стоят чужие, записи ниже нужно добавлять там, где эти серверы управляются.
5. Добавьте запись типа **A**:
   - Имя (поддомен): `@` (означает сам домен, без приставок),
   - Значение (IP-адрес): IP-адрес из шага 5 (вкладка «Дашборд» приложения),
   - TTL оставьте по умолчанию.
6. Добавьте вторую запись, чтобы работал адрес с `www`. Тип **CNAME**, имя `www`, значение ваш домен, например `frsrk.ru.` (с точкой на конце, если reg.ru просит так). Если reg.ru не даёт добавить CNAME, добавьте вторую запись типа **A** с именем `www` и тем же IP.
7. Удалите старые записи типа A и AAAA, если они остались от парковки домена. Иначе домен будет вести на два места сразу.

Если вы хотите, чтобы всей настройкой занимался Timeweb, можно вместо шагов выше указать в reg.ru DNS-серверы Timeweb (`ns1.timeweb.ru`, `ns2.timeweb.ru`, `ns3.timeweb.org`, `ns4.timeweb.org`). Тогда записи создают уже в панели Timeweb, в разделе «Домены». Выберите один из двух способов, не оба сразу.

### 9.2. Сказать Timeweb про домен

1. В Timeweb откройте приложение `frsrk-site` и найдите вкладку про домены (на ней написано **Домены** или **Настройки**, пункт «Привязать домен»).
2. Добавьте ваш домен (без `https://`, например `frsrk.ru`). Добавьте и `www.frsrk.ru`, если хотите, чтобы работали оба.
3. Timeweb сам выпустит бесплатный сертификат безопасности (замочек в адресной строке, значок `https`). Это занимает от нескольких минут до часа после того, как записи в reg.ru заработают.

### 9.3. Подождать

Записи в интернете обновляются не мгновенно. Обычно это от 15 минут до 3 часов, иногда до суток. Проверить можно на сайте dnschecker.org: введите домен и посмотрите, показывает ли он ваш IP.

### 9.4. Сменить адрес в настройках сайта

Когда домен открывается с `https`:

1. В Timeweb откройте приложение, раздел **Переменные**.
2. Замените `NEXT_PUBLIC_SITE_URL` на `https://ВАШ-ДОМЕН` (без слэша на конце).
3. Если хотите, чтобы работал и адрес с `www`, добавьте ещё одну переменную `EXTRA_ORIGINS` со значением `https://www.ВАШ-ДОМЕН`.

Сохраните и перезапустите приложение.

Эта настройка нужна для ссылок в карточках Telegram и VK, карты сайта и защиты входа в админку.

**Как понять, что всё получилось:** `https://ваш-домен/` открывает сайт, `https://ваш-домен/admin` открывает вход в админку, в адресной строке есть замочек.

## Шаг 10. Почта для сайта (по желанию)

Почта нужна, чтобы:
- присылать письмо для восстановления пароля админки,
- получать письмо, когда посетитель написал через форму (иначе сообщения будут только в админке, в разделе «Система → Обращения с сайта»).

Ваш адрес `crimea.skipping@mail.ru` подходит.

1. В Mail.ru откройте настройки почты, раздел **Пароли для внешних приложений** (в настройках безопасности), и создайте пароль для приложения. Обычный пароль от почты сюда не вписывают.
2. В Timeweb, в переменных приложения, добавьте:

| Название | Значение |
|---|---|
| `SMTP_HOST` | `smtp.mail.ru` |
| `SMTP_PORT` | `465` |
| `SMTP_USER` | `crimea.skipping@mail.ru` |
| `SMTP_PASSWORD` | пароль для внешних приложений |
| `SMTP_FROM` | `crimea.skipping@mail.ru` |

3. Перезапустите приложение.
4. В админке откройте **Система → Данные федерации → Служебное** и впишите почту в поле «Куда присылать письма с формы обратной связи».

Если почта не заработала, приложение продолжит работать, просто письма не будут отправляться.

## Как обновлять сайт потом

**Тексты, новости, документы, календарь:** через админку, без Терминала. Инструкция в файле `ИНСТРУКЦИЯ-РЕДАКТОРА.md`.

**Дизайн и код:** изменения отправляются на GitHub, Timeweb сам пересобирает сайт (пункт «Сборка по последнему выполненному коммиту» из шага 5).

```
git add .
git commit -m "Что изменили"
git push
```

Через 5 или 8 минут новая версия работает.

## Резервные копии

- **База данных:** Timeweb делает автоматические копии баз. Откройте вкладку копий в настройках базы и проверьте, что они включены и как долго хранятся.
- **Файлы на складе S3:** отдельные копии Timeweb не делает. Не удаляйте с компьютера папку `seed-assets` и держите там копии важных документов. Все новые файлы, которые вы загрузили через админку, сохраняйте и у себя на компьютере или в облаке.
- Раз в месяц заходите в админку и проверяйте, что всё открывается.

## Что делать, если сломалось

| Что вижу | Что это значит | Что делать |
|---|---|---|
| Деплой упал на этапе сборки | В коде ошибка или не хватило памяти | Откройте журнал деплоя, скопируйте последние 30 строк и покажите разработчику. Попробуйте тариф с 2 ГБ памяти |
| `/api/health` отвечает `error` | Сайт не достучался до базы | Проверьте `DATABASE_URL`: нет ли лишних пробелов, верен ли пароль. Если в журнале слова про SSL или сертификат, добавьте переменную `DATABASE_SSL` со значением `no-verify` |
| Сайт открылся, но без картинок и файлов | Файлы не открываются | Бакет должен быть публичным. Проверьте `S3_PUBLIC_URL` |
| Не могу войти в админку, пишет про CSRF или отказ | Адрес в `NEXT_PUBLIC_SITE_URL` не совпадает с адресом в браузере | Впишите точный адрес сайта с `https://`, без слэша на конце, перезапустите |
| Забыл пароль админки | Нужно восстановить | Нажмите «Забыли пароль?» на странице входа (нужна почта из шага 10). Если почта не настроена, обратитесь к разработчику |
| `npm run seed:prod` пишет про подключение | База не пускает с вашего компьютера | В настройках базы разрешите внешний доступ |
| Домен не открывается | Записи ещё не обновились | Подождите до суток, проверьте на dnschecker.org |
| Замочка нет | Сертификат ещё не выпущен | Подождите час после того, как домен привязан. Проверьте, что нет лишних записей A и AAAA |

## Словарь

- **Сервер** это компьютер, который никогда не выключается и показывает сайт людям.
- **Деплой** это когда новую версию сайта ставят на сервер.
- **База данных** это большая умная таблица, где лежат новости, события, секции.
- **S3, бакет** это склад для файлов. Бакет это одна коробка на складе.
- **DNS** это телефонная книга интернета: она знает, по какому IP-адресу живёт ваш домен.
- **IP-адрес** это номер дома сервера.
- **SSL, https, замочек** это шифрование, чтобы никто не подсмотрел, что передаёт посетитель.
- **Переменные окружения** это настройки и пароли сайта, которые хранятся не в коде, а в панели хостинга.
- **Репозиторий** это папка проекта на GitHub с историей всех изменений.
- **Админка** это закрытая часть сайта для тех, кто им управляет.

## Правила безопасности

1. Файлы `.env` и `.env.prod` никому не отправляйте и не загружайте на GitHub.
2. Пароль администратора не короче 12 символов. Не используйте один пароль на разных сервисах.
3. Редакторам давайте роль «Редактор», а не «Администратор».
4. Если кто-то из сотрудников уходит, удалите его в разделе «Система → Сотрудники».
5. Публикуйте фото детей и списки спортсменов только с согласия родителей.
