# Как устроен код

## Схема

```
Посетитель ──► Next.js (Timeweb App Platform, Docker)
                 ├─ публичные страницы  src/app/(frontend)
                 ├─ админка             src/app/(payload)  (/admin)
                 └─ Payload CMS         src/payload.config.ts
                        ├─ PostgreSQL (Timeweb)  ← тексты, записи, справочники
                        └─ S3 (Timeweb)          ← все загруженные файлы
```

Файлы отдаёт S3 напрямую по публичным ссылкам: сайт не тратит на них ресурсы, аудио можно перематывать.

## Папки

| Путь | Что там |
|---|---|
| `src/collections/` | Описание всех разделов админки: пользователи, изображения, документы, музыка, видео, новости, календарь, секции, люди, страницы, фотоальбомы, рейтинг, обращения |
| `src/globals/SiteSettings.ts` | «Данные федерации»: название, контакты, реквизиты |
| `src/access/` | Правила доступа: кто что видит и меняет |
| `src/hooks/` | Автоматизация: адреса из названий, русские имена файлов в латиницу, сброс кеша после правок |
| `src/lib/cms.ts` | Единственное место, где публичные страницы читают базу (с кешем) |
| `src/lib/` | Даты, статусы мероприятий, справочники, проверка настроек |
| `src/app/(frontend)/` | Публичные страницы и `globals.css` (весь дизайн) |
| `src/components/section/` | Общий шаблон разделов «слева пункты, справа содержимое» (Участникам, О федерации, Документы) |
| `src/config/sections.ts` | Пункты боковых меню разделов «Участникам» и «О федерации» |
| `src/components/` | Шапка, подвал, карта, список секций, форма, строки документов |
| `src/data/crimea-map.json` | Контуры 25 муниципальных образований Крыма и Севастополя (OpenStreetMap, упрощены) |
| `src/migrations/` | Миграции базы. Применяются на сервере при запуске |
| `scripts/` | `seed.ts` (первичная загрузка), `prepare-assets.ts` (подготовка картинок) |
| `content/pages/` | Исходные тексты страниц для первой загрузки (Markdown) |
| `seed-assets/` | Файлы для первой загрузки. В git не попадают |
| `tests/` | Тесты |

## Решения

- **Payload вместо своей админки.** Готовые роли, загрузка файлов в S3, история изменений, русский интерфейс.
- **Файлы вне сайта.** Иначе образ сайта раздувается, а любое обновление документа требует новой сборки.
- **Публикация галочкой.** Понятнее редакторам, чем версии и черновики.
- **Статус мероприятия по датам.** Не хранится, поэтому не может устареть.
- **Публичные страницы динамические с кешем.** Сборка не требует базы. После любой правки в админке кеш сбрасывается (`src/hooks/revalidate.ts`), а на всякий случай он живёт не дольше 5 минут.
- **Карта без сторонних библиотек.** Свой SVG, не грузит внешние карты и не отслеживает посетителей.
- **Миграции при запуске.** `prodMigrations` в конфиге базы: контейнер сам приводит базу в порядок.
- **Схема базы зависит от S3.** Плагин хранилища добавляет колонки. Поэтому миграции создают с заполненными переменными S3 (см. README).

## Безопасность

- Роли и права: `src/access/index.ts`. Редактор не может создавать пользователей и менять роли.
- Публичное чтение: только `published = true`, применяется во всех запросах (`overrideAccess: false`).
- Закрытая форма: `/api/inquiries` проверяет данные (zod), скрытое поле-ловушка, ограничение частоты.
- Заголовки безопасности: `next.config.mjs` (nosniff, X-Frame-Options, HSTS для https).
- Файлам даются латинские имена со случайным хвостом, чтобы неопубликованные документы нельзя было угадать. Это не защита, а уменьшение риска: не публикуйте секреты.
- Yandex.Метрика подключается только после согласия посетителя.
- Зависимости проверены `npm audit`: уязвимостей нет (используются переопределения версий в `package.json`).
